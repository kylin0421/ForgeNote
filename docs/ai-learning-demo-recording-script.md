# ForgeNote「ai学习」录屏展示稿

## 视频定位

- 建议时长：4 分钟左右。
- 建议标题：**ForgeNote：从理解学生到持续进化的 AI 学习工作台**
- 主线：**动态画像 → 个性化对话 → 资料搜集 → Agent 监督 → 多模态 Studio → Quiz → 画像回写**
- 主题：用 Transformer 的 Q、K、V 演示一轮完整学习闭环。

`ai学习` 使用正式 Notebook 的画像访谈、三栏工作区、资料搜集、Agent 监督台、Studio 资产卡和预览组件。演示只把模型回答、检索结果和生成产物预先缓存，避免录制时等待；按钮、媒体和 Quiz 仍可真实操作。

> 面向观众时把它当作普通学习记录讲解，不要介绍“演示模式”“缓存步骤”或键盘控制。

## 录制前准备

1. 启动前端、API、数据库和任务 Worker。
2. 用 Chrome 打开 `http://127.0.0.1:3000/notebooks`。
3. 使用 1920×1080，浏览器缩放 90%～100%，隐藏书签栏和无关通知。
4. 点击 `ai学习` 后从头试走一次，确认博客、图片、导图、播客、51 秒讲解视频、字幕和 Quiz 都能打开。
5. 媒体播放完先暂停，再点击标题或空白处清除焦点；输入框、按钮或播放器获得焦点时，空格会保留给当前控件。

### 重置

返回学习记录列表，再次点击 `ai学习`。它会重新从正式“创建新笔记本”弹窗开始，画像、来源、对话和资产不会继承上一次演示状态。

## 录制注意点

- step 0 是正式新建弹窗；step 1 是画像首问；step 2 展示回答与完整画像；step 3 才进入 0 来源的空白三栏工作区。
- 资料搜集始终发生在 Notebook 中间栏，不要说“进入独立 DeepSearch 页面”。
- step 8 已是 4 条资料采纳完成并写回 Notebook 的状态；后续来源数必须始终为 4。
- step 12 要同时拍到 5 项就绪和视频仍在生成，避免“全部生成中”与进度矛盾。
- step 13 必须真实打开博客，播放播客和视频；视频至少拍到一段配音、一个画面转场和字幕。
- 博客卡片、弹窗标题和正文 H1 统一为“为什么注意力不是‘查字典’？用一组数字真正算懂 Q、K、V”。
- 第四个外部资料应直接打开 StatQuest 正式视频，而不是 YouTube 搜索结果。
- UI 不显示“空格”“步骤数”或“演示模式”提示；这些操作说明只保留在本录制稿。
